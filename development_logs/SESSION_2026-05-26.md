## 1. 개요 (Summary)

이 날의 작업은 **기능 문제 관련 전반적인 개선**을 목적으로 진행되었다. 크게 세 가지 축으로 나눌 수 있다.

1. **백엔드(FastAPI) 개선**: `read_books` 테이블에 `user_id` 컬럼을 추가하여 사용자별 독서 기록 소유권을 부여하고, 책 조회 API에 사용자 필터링 기능을 추가하였다. 또한 환경 변수 로딩 경로 문제를 해결하여 Docker 환경과 로컬 환경 모두에서 안정적으로 동작하도록 수정하였다.

2. **프론트엔드(React) 리팩토링**: 기존 `App.jsx` 하나에 몰려 있던 2000줄 이상의 코드를 **탭별 컴포넌트**와 **모달 컴포넌트**로 분리하여, 유지보수성과 가독성을 대폭 향상시켰다. 공통 유틸 함수 및 상수도 별도 파일로 분리하였다.

3. **인프라(Docker) 개선**: `docker-compose.yml`에 `backend` 서비스를 추가하여 전체 스택을 컨테이너 환경에서 일괄 관리할 수 있도록 구성하였다.

## 2. 주요 변경 사항 및 구현 세부 정보

---

### 🗄️ 백엔드 — `agent/db.py`

**변경 목적**: `read_books` 테이블에 사용자 소유권 개념 도입

- 기존 주석 `# 읽은 책 감상평/공개여부`를 `# 읽은 책 감상평/공개여부/소유자`로 변경하여 의미를 명확히 함.
- `read_books` 테이블에 `user_id` 컬럼을 추가하는 `ALTER TABLE` 구문을 신규 추가:
  ```sql
  ALTER TABLE read_books ADD COLUMN IF NOT EXISTS user_id INTEGER REFERENCES users(id) ON DELETE SET NULL
  ```
  - `users(id)`를 외래 키로 참조하며, 유저가 삭제되어도 책 기록은 유지되도록 `ON DELETE SET NULL` 정책을 적용.
  - `IF NOT EXISTS`를 사용하여 서버 재시작 시 중복 실행에도 안전하게 처리.

---

### ⚙️ 백엔드 — `agent/main.py`

**변경 목적**: 환경 변수 로딩 경로 문제 해결 (Docker vs 로컬 실행 호환성)

- `pathlib.Path` 임포트 추가.
- 기존 `load_dotenv()` 단독 호출 이후, 추가로 `backend/.env` 경로를 명시적으로 로드하는 코드 추가:
  ```python
  load_dotenv(Path(__file__).parent.parent / "backend" / ".env")
  ```
- **동작 방식**:
  - Docker 환경: `docker-compose`가 `env_file`로 환경 변수를 직접 주입하므로 두 번째 `load_dotenv`는 무시됨.
  - 로컬 직접 실행 환경: `agent/.env` → `backend/.env` 순으로 로드하여 필요한 환경 변수를 모두 획득.
