# 작업 세션 — 2026-07-29

---

## 1. 개요 (Summary)

이번 세션은 크게 다섯 축으로 진행되었다.

1. **독서모임(DiveRoomModal) 실시간화·정확성 개선** — 웹소켓 도입(채팅/참가자 변동 실시간 반영), 대기 화면 분리, 참가 마감시간 버그 수정, 채팅 중복 표시 버그 수정
2. **독서시간 기록 정확도 개선** — 세션별 기록 → (유저,책) 단위 누적 방식 전환, 책과 연결 안 된 기록 보정, 개인 서재에서 책별 독서시간 + 다른 유저 독서시간 공개
3. **소셜 관계 단순화** — 친구/팔로우 이원화된 구조를 "친구" 하나로 통합, 관계 변경(친구/차단) 시 확인 팝업 추가
4. **커뮤니티 게시글 ↔ 도서 연결** — 수동 선택 시 isbn 저장 버그 수정, AI가 게시글 내용을 읽고 책을 자동 추정해 태깅(확인/수정/해제 가능)
5. **AI 페르소나 시스템 신설** — 독서모임 토론 준비를 돕는 8종 캐릭터 설계, 텍스트 기반 검증, 프로필 사전 선택 + 다이브룸 내 개인 AI 대화창 구현

그 외 관리자 페이지 점검, 모임찾기(클럽) 탭 임시 비활성화, 녹음 분석 기능 점검(원인 파악), 저장소 정리(불필요 파일 삭제) 등을 진행했다.

## 2. 주요 변경 사항 및 구현 세부 정보

### 2-1. 독서모임 실시간화 (`agent/routers/dive.py`, `frontend/src/components/modals/DiveRoomModal.jsx`)

**왜:** 새 참가자가 들어와도 이미 방에 있던 사람 화면엔 반영이 안 됐고(수동 새로고침 필요), 채팅도 5초 폴링이라 토론 중 대화가 답답했다.

- 방 하나당 웹소켓 연결(`/api/dive/rooms/{room_id}/ws`, 참가자만 인증 후 접속 허용)을 도입해 채팅을 실시간 push로 전환. 폴링 제거.
- 참가/퇴장/추방/상태변경/방상태변경 시점에 `room_update` 이벤트를 방 전체에 브로드캐스트 → 받은 클라이언트가 즉시 재조회. 참가자 목록이 새로고침 없이 실시간으로 갱신됨.
- **버그 수정 — 채팅 중복 표시:** 메시지 전송 시 서버가 (1) 웹소켓 브로드캐스트 (2) HTTP 응답, 두 경로로 같은 메시지를 돌려주는데 브로드캐스트가 먼저 도착하는 경우가 있어 보낸 사람 화면에 메시지가 두 번 찍혔다. HTTP 응답 처리 쪽에도 id 기준 중복 체크를 추가해 해결.

### 2-2. 대기 화면 분리 (`frontend/src/components/modals/DiveRoomModal.jsx`)

**왜:** 독서 시작 전 대기 화면인데도 진행 중 화면과 똑같이 큰 모달(화면의 85%)을 그대로 써서, 보여줄 정보가 적은데 불필요하게 커 보였다.

- 같은 컴포넌트 안에서 `computedPhase === 'waiting'`일 때 별도의 작은 화면(제목/배지, 방장, 예정시간·독서시간·토론시간·인원, 공지, 참가 예정 명단)을 반환하도록 분리. 독서 시작 시각이 되면 자동으로 기존의 큰 화면(채팅+참가자)으로 전환됨.
- 별도 모달 컴포넌트로 만들지 않고 같은 함수 내 조건부 반환으로 처리한 이유: 방 데이터 조회·웹소켓 연결·참가자 상태를 이미 한 컴포넌트가 들고 있어서, 분리하면 그 상태들을 중복 관리해야 하기 때문.

### 2-3. 참가 마감시간(late_join_cutoff_minutes) 버그 수정 (`agent/routers/dive.py`)

**왜:** 방 생성 시 "OO분 전 마감"을 설정할 수 있고 화면에도 표시되는데, 실제 참가(`join_room`) 로직에는 이 값을 검사하는 코드가 아예 없었다 — 설정이 화면 표시용일 뿐 실제로는 아무 때나 참가가 가능했던 진짜 버그.

- `join_room`에 `datetime.now() >= scheduled_at - cutoff_minutes`이면 참가를 거부하는 검사 추가.

### 2-4. 방장 도서 선택 필수화 (`agent/routers/dive.py`, `frontend/src/components/modals/CreateDiveRoomModal.jsx`)

**왜:** 지정 도서 없는(자유도서) 방을 만들면 참가자는 입장 시 책을 고르지만, 방장은 방 생성 시 자동 참가 처리만 되고 책을 고르는 절차가 없어서 방장 본인의 독서시간이 어떤 책과도 연결되지 않는 구조적 공백이 있었다.

- 방 생성 폼에 자유도서일 때만 나타나는 "내가 읽을 책 *" 필수 검색란 추가.
- 백엔드도 동일 조건(지정도서 없고 방장 책도 없음)이면 방 생성 자체를 거부하도록 이중 검증.

### 2-5. 독서시간 기록 방식 전환 — 세션별 → (유저,책) 누적 (`agent/db.py`, `agent/routers/reading.py`, `agent/routers/dive.py`)

**왜:** 기존엔 읽을 때마다(타이머 종료, 다이브룸 세션 종료) `reading_logs`에 새 행이 계속 쌓였다. 중단했다 재개해도 같은 책에 대한 기록이 여러 줄로 흩어지는 구조였고, 정리해서 보여줄 필요가 없다는 요청에 따라 누적 방식으로 전환.

- `reading_logs`에 `UNIQUE(user_id, read_book_id)` 제약 추가, `INSERT ... ON CONFLICT DO UPDATE SET duration_seconds = 기존값 + 새값` 방식으로 변경. 같은 책을 다시 읽으면 새 행이 아니라 기존 행에 더해짐.
- **기존 데이터 정리(1회성 마이그레이션, `_init_db()`에 포함):** 이미 쌓여있던 (유저,책) 중복 행을 하나로 합치고, 책과 연결 안 된(NULL) 기존 기록은 그 유저가 이미 기록을 가진 다른 책에 병합. 실제 DB에 적용해 확인 완료 — 남은 미연결 기록은 전부 "합칠 다른 책 자체가 없는" 유저였고, 이는 정상 케이스.
- `_log_reading_time`(다이브룸)에도 같은 폴백 추가: 책 정보로 매칭 실패 시, 이미 기록이 있는 다른 책에 합침. **주석으로 명시:** 방장/참가자 모두 책 선택이 필수가 된 지금은 이 폴백이 "책은 골랐지만 아직 내 서재에 등록 안 된 책"인 경우에만 발동해야 정상이며, 이 케이스마저 없어지면(예: 선택한 책을 자동으로 서재에 등록하는 방식으로 개선하면) 폴백 자체를 삭제해도 된다는 TODO를 남겨둠 — 나중에 잊고 방치되지 않도록.

### 2-6. 개인 서재 — 책별 독서시간 공개 (`frontend/src/components/modals/UserLibraryModal.jsx`, `agent/routers/books.py`, `agent/routers/reading.py`)

**왜:** 독서시간이 책 단위로 정리된 김에, 책 하나를 눌렀을 때 "내가 이 책을 얼마나 읽었는지"와 "다른 사람들은 얼마나 읽었는지"를 바로 볼 수 있으면 좋겠다는 요청. 별도의 "책 상세 화면"을 새로 만들 필요 없이, 기존 서재의 책 카드를 펼치는 것으로 충분하다고 판단.

- `GET /api/books/read`에 책별 누적 시간(`my_seconds`) 추가.
- `GET /api/reading/book-readers?isbn=` (또는 `title=`) 신규 — 같은 책을 읽은 다른 유저들의 이름·시간 목록. `stats_public` 설정을 따름.
- 책 카드 클릭 조건을 "감상이 있을 때만"에서 항상 클릭 가능하도록 변경, 펼치면 감상(있으면) 아래에 두 섹션 추가.

### 2-7. 친구·팔로우 통합 (`agent/routers/users.py`, `frontend/src/components/modals/UserLibraryModal.jsx`)

**왜:** 친구(요청→수락 방식)와 팔로우(일방향)가 별개 시스템으로 공존해서 사용자 입장에서 관계가 이원화되어 혼란스러웠다.

- 팔로우 관련 백엔드 엔드포인트(`follow`/`unfollow`/`following`/`followers`) 전부 제거. 관계는 친구 하나로 통일.
- 내 서재의 "팔로우" 탭 → "친구" 탭으로 교체, 실제 친구 목록(`GET /api/friends`)을 보여주고 "친구 끊기" 제공.
- 상대방 프로필의 관계 탭도 친구+차단 카드만 남김.
- **추가 개선:** 친구/차단 버튼 클릭 시 바로 실행되지 않고 확인 문구 + 취소/확인 버튼이 뜨도록 변경 (실수 클릭 방지).

### 2-8. 참가자 추방 UI를 팝업으로 변경 (`frontend/src/components/modals/DiveRoomModal.jsx`)

**왜:** 기존엔 화면 하단에 묻히는 인라인 배너 형태라 눈에 잘 안 띄었다.

- 화면 중앙에 어두운 배경과 함께 뜨는 별도 팝업으로 변경. 방 모달보다 위 레이어(z-index)에 배치.

### 2-9. 독서 시간 종료 알림 강화 (`frontend/src/components/modals/DiveRoomModal.jsx`)

**왜:** 예정된 독서+토론 시간이 다 지나도 방은 자동으로 닫히지 않는데(의도된 동작 — 더 읽고 싶은 사람 배려), 이 사실을 알리는 게 4초 만에 사라지는 작은 토스트뿐이라 놓치기 쉬웠다.

- 확인이 필요한 모달 팝업으로 교체. 방장에게는 팝업에서 바로 "지금 종료하기" 버튼 제공.
- 참가자 상태 뱃지도 실제 진행 단계를 반영하도록 수정 (토론 단계에서 "독서 중"으로 잘못 표시되던 버그 수정). 토론 시간 종료 후 계속 읽는 시간도 실제로 독서시간에 집계되도록 계산 로직 보정.

### 2-10. 커뮤니티 게시글 ↔ 도서 연결 (`agent/routers/community.py`, `agent/nodes/infer_book_from_post.py`, `frontend/src/components/modals/WritePostModal.jsx`, `frontend/src/components/modals/PostModal.jsx`)

**왜:** 게시글 작성 시 책을 검색해서 고르는 UI가 이미 있었는데 실제 저장 시 isbn이 버려지고 있었음(버그). 또한 글쓸 때마다 책을 강제로 고르게 하면 번거로우니, 안 고르고 써도 AI가 내용을 보고 책을 추정해주면 좋겠다는 요청.

- 수동 선택 시 isbn·이미지를 실제로 저장하도록 수정 (`book_tag_source='manual'`, 확정 상태).
- 책 선택 없이 작성된 글은 저장 후 백그라운드에서 Claude가 제목+본문을 읽고 책을 추정 → 네이버 도서 검색으로 isbn 확정 → **미확인(unconfirmed) 상태**로 저장.
- 게시글 상세에 "AI가 추정한 책: OOO. 맞나요?" 확인 UI. 작성자만 확인/수정/해제 가능. 확인 전까지는 피드 카드에도 "AI 추정" 표시로 다른 사용자에게도 미확정임을 알림.

### 2-11. AI 페르소나 시스템 (`CHARACTER_PERSONAS.md`, `agent/nodes/persona_chat.py`, `frontend/src/personas.js`)

**왜:** 독서모임 토론 준비에 AI가 관여할 때, 고정된 톤 하나보다 여러 캐릭터 페르소나(질문 스타일이 다른) 중 골라 쓸 수 있으면 접근성과 재미가 좋아질 것이라는 아이디어에서 출발.

- 8종 페르소나 설계 (호기심 많은 어린이/경제 청년/철학적 중년/사춘기 청소년/은퇴자/도전하는 실행가/비판적 사고 훈련형/관계 치유형-수달). 각각 "왜 이 캐릭터인가"(대상 독자·목적)까지 `CHARACTER_PERSONAS.md`에 문서화.
  - 원칙: 기본은 사람 캐릭터, 정서·관계 중심 페르소나 1개만 동물(수달) 예외.
- 실제 Claude API로 텍스트 검증 완료 (동일 소재로 8개 페르소나 질문 스타일이 확실히 갈리는 것 확인). 검증 방법·결과 전부 문서에 기록.
- 이미지 원화 5/8종 완료 (Gemini로 생성), 나머지 3종(실행가/비판적사고/수달)은 미완성.
- 프로필("내 서재")에서 페르소나 사전 선택 → `users.ai_persona` 저장.
- 독서모임 내 별도 AI 대화창 구현 — 메인 방 채팅과 완전히 분리된 개인 전용 창. **토론 시작 10분 전 자동으로 열리며** 책을 다 읽었는지, 정리하고 싶은 생각이 있는지 먼저 말을 검. 독서·토론 단계 내내 접었다 펼 수 있음.
  - 최초엔 원형 아이콘 버튼만 있어서 재오픈 방법을 못 알아챌 수 있다는 지적에 따라 "AI와 토론 준비 대화하기" 텍스트가 항상 보이는 알약형 버튼으로 변경.
  - 응답 대기 중 로딩 표시를 🤔 옆에 ☁️가 좌우로 떠다니는 애니메이션으로 구현.

## 3. 기타 점검 및 정리

- **모임찾기(클럽) 탭**: 데이터/기능은 그대로 두고 상단 탭 선택지에서만 제거 (추후 완전히 없앨 예정이라 우선 숨김 처리만).
- **녹음 분석 기능 점검**: 코드 자체는 완성 상태(Whisper 전사 → pyannote 화자분리 → Claude 분석). 다만 `HUGGINGFACE_TOKEN`이 `.env`에 없어 화자분리 단계에서 막히고, 이 실패를 감싸는 예외처리가 없어 요청 전체가 500 에러로 실패하는 상태였음. 원인 안내만 하고 토큰 발급은 사용자가 직접 진행하기로 함(HuggingFace 계정 필요 + 게이트 모델 약관 동의 필요해서 대행 불가).
- **저장소 정리**: 루트의 `query`(내용 없는 stray 파일), `demo_analysis.json`(디버깅 중 실수로 커밋된 에러 텍스트) 삭제. `backend/` 폴더는 레거시 Node.js로 README에 "참고용 보존"이라 명시되어 있어 삭제하지 않음 — 다만 `docker-compose.yml`이 지금도 이 폴더의 `.env`를 agent 서비스 환경변수로 쓰고 있어, 레거시 폴더에 현재 스택이 의존하는 구조라는 점은 참고로 남김.

```
(HTTP code 500) server error - ports are not available:
exposing port TCP 0.0.0.0:8080 -> 127.0.0.1:0:
listen tcp 0.0.0.0:8080: bind:
An attempt was made to access a socket in a way forbidden by its access permissions.
```

**원인 진단:**
1. `netstat -ano | findstr ":8080"` → 실제로 8080번을 점유 중인 프로세스는 없음 (단순 "포트 사용 중" 충돌이 아님).
2. `netsh interface ipv4 show excludedportrange protocol=tcp` 결과, Windows가 `8021~8120` 범위를 TCP 포트 제외(예약) 구간으로 잡고 있었고 8080이 정확히 그 범위 안에 포함됨.
3. 이건 WSL2/Hyper-V가 재부팅·절전·업데이트 등을 거치며 포트 범위를 임의로 예약해가는 Windows의 알려진 동작이며, 에러 메시지의 "forbidden by its access permissions" 문구가 이 문제의 전형적인 증상이다. 즉 Docker의 문제가 아니라 Windows 네트워킹 스택이 그 포트 자체를 아무 프로세스도 못 쓰게 막아둔 상태였음.

**해결 방법 (관리자 권한 필요, 사용자가 직접 실행):**
```
net stop winnat
net start winnat
```
`winnat`(Windows NAT) 서비스를 재시작하면 포트 예약 범위가 초기화되어 대부분 해결된다. 필요시 Docker Desktop 자체 재시작도 병행.

**재발 시 참고:** 같은 증상이 다시 나타나면 `netsh interface ipv4 show excludedportrange protocol=tcp`로 8080이 다시 제외 범위에 들어갔는지부터 확인하면 원인 파악이 빠르다. 근본적으로 피하고 싶다면 `docker-compose.yml`의 프론트엔드 호스트 포트를 8080 대신 다른 값(예: 8090)으로 바꾸는 것도 우회책이 될 수 있음 (다만 URL이 바뀌는 트레이드오프 있음).
