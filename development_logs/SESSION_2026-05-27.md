# 작업 세션 — 2026-05-27

---

## 1. 개요 (Summary)

이번 세션에서는 독서 커뮤니티 앱의 **서재(Stack)**, **커뮤니티(Community)** 기능을 중심으로 다수의 기능을 추가하고 기존 버그를 수정하였다. 주요 작업은 크게 다섯 가지 방향으로 진행되었다:

1. **읽은 책 삭제 기능 추가** — 서재에서 등록한 책을 직접 삭제할 수 있는 API 및 UI 구현
2. **커뮤니티 게시물 페이지네이션 도입** — 게시물 목록에 페이지 기반 무한 스크롤(더보기) 기능 추가
3. **게시물 삭제 기능 추가** — 본인이 작성한 게시물을 삭제할 수 있는 API 및 UI 구현
4. **로그아웃 기능 추가** — 헤더에 로그아웃 버튼 신설
5. **DB 스키마 보완** — `read_books`, `clubs`, `comments` 테이블에 누락된 컬럼 추가 및 하위 호환성 보정
6. **추천 API 버그 수정** — 책 추천 쿼리가 전체 사용자 데이터를 참조하던 문제를 특정 유저 기준으로 수정

### 📄 `agent/routers/books.py`

#### ✅ 읽은 책 삭제 엔드포인트 추가

```python
@router.delete("/read/{book_id}")
def delete_read_book(book_id: int, conn=Depends(get_db)):
```

- `DELETE /api/books/read/{book_id}` 엔드포인트를 새로 추가하였다.
- `read_books` 테이블에서 해당 `id`를 조건으로 `DELETE ... RETURNING id` 쿼리를 실행하며, 존재하지 않는 ID일 경우 `404 HTTPException`을 반환한다.

### 📄 `agent/routers/community.py`

#### ✅ 게시물 목록 API에 페이지네이션 파라미터 추가

- `get_posts` 함수의 시그니처에 `page: int = 1`, `limit: int = 20` 파라미터를 추가하였다.
- `offset = (max(1, page) - 1) * limit` 공식으로 SQL `LIMIT / OFFSET`을 적용하여 페이지 단위 조회가 가능해졌다.
- 응답 구조를 단순 배열에서 아래 구조로 변경하였다:
  ```json
  {
    "posts": [...],
    "total": 42,
    "page": 1,
    "limit": 20
  }
  ```
- `SELECT COUNT(*) FROM posts` 추가 쿼리를 통해 전체 게시물 수(`total`)를 함께 반환, 프론트엔드에서 "더 보기" 여부를 판단할 수 있도록 하였다.
