# 작업 세션 — 2026-07-05

## 1. 개요 (Summary)

오늘은 독서 앱의 핵심 소셜 기능군을 대거 추가한 날이다. 크게 네 가지 축으로 개발이 진행되었다.

1. **독서모임 Dive** — 실시간 독서 세션을 위한 방 개설/참가/채팅/상태관리 풀스택 구현
2. **인상깊은 문장(Highlights)** — 책에서 발췌한 문장을 저장·삭제하는 기능
3. **소셜 로그인(OAuth)** — 카카오 / 네이버 / 구글 소셜 로그인 인프라 연결
4. **친구 기능(Friends)** — 친구 요청·수락·삭제 API 및 프론트엔드 UI

총 10개 파일이 변경되었으며, 순 추가 코드 기준 약 1,472줄이 삽입되었다. 백엔드(FastAPI + PostgreSQL)와 프론트엔드(React) 양쪽을 동시에 작업하여 기능 단위로 완결된 형태로 배포 가능한 상태를 유지했다.

## 2. 주요 변경 사항 및 구현 세부 정보

### 2-1. 데이터베이스 스키마 확장 (`agent/db.py`)

#### 커밋 85dd351 — 유저 관련 수정
- **`read_books` 테이블**: `description TEXT DEFAULT ''` 컬럼 추가. 책 등록 시 책 소개(설명)를 함께 저장할 수 있도록 스키마 확장.
- **`users` 테이블**: 소셜 로그인 지원을 위해 세 컬럼 추가.
  - `email VARCHAR(200)` — 이메일 기반 계정 연동에 사용
  - `oauth_provider VARCHAR(20)` — 'kakao' / 'naver' / 'google' 구분
  - `oauth_id VARCHAR(100)` — 각 OAuth 공급자의 고유 식별자
- **`friendships` 테이블 신규 생성**: 친구 관계를 저장하는 테이블. `requester_id`, `addressee_id` 간의 관계를 `pending` / `accepted` 상태로 관리. `UNIQUE(requester_id, addressee_id)` 제약으로 중복 요청 방지.

#### 커밋 b5a6e41 — Dive 기능
- **`highlights` 테이블 신규 생성**: 사용자가 특정 책(`read_book_id`)에서 발췌한 문장(`text`)과 페이지 번호(`page_num`)를 저장. 책 삭제 시 연쇄 삭제(`ON DELETE CASCADE`).
- **`dive_rooms` 테이블 신규 생성**: 독서모임 방의 메타데이터 저장.
  - 방 제목, 책 정보(제목/이미지/ISBN), 방장 정보, 예정 시간(`scheduled_at TIMESTAMPTZ`)
  - 독서 시간(`reading_minutes`), 토론 시간(`discussion_minutes`), 최대 인원(`max_participants`), 늦게 참가 허용 시간(`late_join_cutoff_minutes`) 등 세밀한 설정값 보관
  - `status VARCHAR(20) DEFAULT 'scheduled'` — 방 상태 머신(`scheduled` → `reading` → `discussion` → `ended`) 관리
- **`dive_participants` 테이블 신규 생성**: 방-사용자 N:M 참가 관계 저장. `UNIQUE(room_id, user_id)`로 중복 참가 방지.
- **`dive_messages` 테이블 신규 생성**: 방 내 채팅 메시지 저장. AI 메시지 여부(`is_ai BOOLEAN`)를 별도 컬럼으로 구분.
